## Why this report gives ratios

The laptop was shared with other benchmark jobs. It has 16 logical CPUs, and
the one-minute load stayed between 10.26 and 16.94 for the whole session,
above half the cores. Pinning a worker to one CPU does not reserve that CPU,
so absolute MB/s from this session are lower than a quiet run would give and
vary from run to run. A ratio between two engines measured minutes apart in
the same run is less affected, so the tables below give ratios and their
range. The raw records keep every sample.

For the same reason `RESULTS.md`, the headline table in the README and the
core and full-corpus charts keep the 21 October merged-main snapshot.
`COMPARISON.md` and the shared JavaScript report are written by their runners
and carry this session's MB/s; read them as same-run comparisons only.

## Core route: Carve against its fastest same-language peer

`scripts/compare-dev-main.mjs` ran three times: 18-point fixture with pipe
tables, two rounds in reversed engine order, seven trials per round. Each ratio
is the peer's median process CPU time divided by Carve's, so a value above
1.00x means Carve is faster.

| Language | Peer | Run 1 | Run 2 | Run 3 | Median | 21 October snapshot |
|---|---|---:|---:|---:|---:|---:|
| Rust | pulldown-cmark | 1.13x | 1.18x | 0.99x | 1.13x | 1.11x |
| JavaScript | djot.js or markdown-it, whichever was faster | 4.01x | 3.44x | 3.30x | 3.44x | 1.89x |
| PHP | djot-php | 0.82x | 0.97x | 0.97x | 0.97x | 1.00x |

| Run | Finished (UTC) | CPU | One-minute load, start | End | Raw record |
|---|---|---:|---:|---:|---|
| 1 | 13:22 | 13 | 15.41 | 16.94 | [run 1](main-core-20261112-run1.json) |
| 2 | 13:30 | 12 | 12.33 | 11.31 | [run 2](main-core-20261112-run2.json) |
| 3 | 13:38 | 13 | 12.23 | 11.25 | [run 3](main-core-20261112-run3.json) |

The JavaScript ratio is well above the October one, and this session cannot
say how much of that is carve-js. Against the October snapshot's process CPU
throughput, carve-js ran between 4% lower and 31% higher across the three
runs, while djot.js and markdown-it ran 19% to 51% lower. The peers' drop is
larger than anything the Rust and PHP rows show, so the JavaScript ratio is
the least certain of the three. Rust and PHP are within their run-to-run
range of the October snapshot.

`compare.mjs` on the same checkouts ([COMPARISON.md](../COMPARISON.md), wall
time, five trials, load 11.47 to 12.28) gave Rust 1.03x, JavaScript 3.42x and
PHP 1.08x.

All three runs used one Rust comparison binary (SHA-256 `151adcfdd86b...`,
full value in the records) built with [this dependency lock](main-core-20261112-rust.Cargo.lock).

## Shared JavaScript workload: carve-js against commonmark.js

`scripts/compare-commonmark.mjs --carve-main` on CPU 13, load 15.53 at start
and 10.90 at end. Source: [the shared report](commonmark-js.md).

| carve-js | Median ms/op | commonmark.js ms/op | carve-js against commonmark.js |
|---|---:|---:|---:|
| 0.1.15 (26 October run) | 3.19 | 4.49 | 1.41x faster |
| 0.1.16 ([12 November release run](commonmark-js-release-0.1.16.md), another host) | 122.54 | 8.89 | 13.8x slower |
| main `efef22a` (this run) | 2.81 | 5.20 | 1.85x faster |

The 0.1.16 slowdown on this workload came from #6026 and is gone on main.
