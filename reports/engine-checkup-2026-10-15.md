# Engine checkup, 2026-10-15

These samples compare the pinned engines with commits taken from each engine's merged `main`. The host was shared and had 16 logical CPUs. The [raw samples and provenance](data/engine-checkup-2026-10-15) retain input hashes, observations, commits, and runtime settings. On 2026-10-15, the PHP phase and memory probes finished at 16:47 and 16:48 CEST, the paired wall run at 17:21 CEST, the CPU run at 17:53 CEST, and the Rust allocation probe at 18:05 CEST. The PHP memory probe used `php -n` with `ctype` and `mbstring` enabled, so JIT and opcache were off. The one-off runner scripts remained local; the archived samples and fixture bases support review but do not reproduce the runs by themselves.

Node was 22.22.2, PHP was 8.5.11, and rustc was 1.97.1. The comparison input is `corpus/small.crv` (1,233 bytes, SHA-256 `e59b53242d55149997deab060fe0fb326b9dfaa5548b4c1f600a4c1daff4dec3`). Medium and large join 50 and 400 copies with one newline between copies, giving 61,699 and 493,599 bytes. The AST variant adds one 45-byte footnote to those inputs, giving 61,744 and 493,644 bytes; [ast-base.crv](data/engine-checkup-2026-10-15/ast-base.crv) shows the small version. The comparison input contains an image and a cross-reference, which sends JavaScript through its AST route. The older benchmark name `core` does not describe its route.

Fresh processes warmed each engine, then ran alternating pin/main pairs. The wall run used two ABBA rounds with PHP JIT enabled; the JS and Rust CPU run used four ABBA rounds. The separate PHP phase run used two reversed rounds with JIT off. The CPU run began with a 1-minute host load average of 30.7, and the wall run began at 10.9. Ratios near 10% are uncertain on this host. The [output hashes](data/engine-checkup-2026-10-15/output-hashes.json) show that the September mixed corpus produced different output between the pin and main in all three engines, so its time ratios do not compare equivalent work. The memory and allocation probes took one sample per depth and phase.

## Findings

JavaScript's measured main took 1.20 times the pin's CPU time on the medium comparison input, with all eight main samples above all eight pin samples. The large comparison input had a 1.23 CPU median ratio but wide overlap; the AST variant's medium CPU ratio was 1.00. The wall run measured a 0.92 ratio on the large comparison input. A later render-only investigation traced a separate renderer cost to repeated full-tree hydration of empty references. [The renderer fix](https://github.com/markup-carve/carve-js/pull/3172) has since merged. The paired CPU samples here predate that fix.

PHP's fixed-input AST wall ratios were 1.05 at medium size and 0.97 at large size. The comparison input's large wall ratio was 1.12, with high sample spread. Its no-JIT phase medians ranged from 0.88 to 1.09 times the pin across brackets, partial brackets, lists, quotes, and paragraphs. The depth-192 list parse peak rose from 3,924,712 to 4,929,144 bytes above start, while retained memory fell from 228,648 to 183,080 bytes. The depth-192 quote parse peak rose from 1,910,184 to 2,172,328 bytes. Both were transient parser memory increases. Depth-192 quote and list render peak memory matched at pin and main: 263,864 and 788,152 bytes above start, respectively. Both revisions' [HTML renderer](https://github.com/markup-carve/carve-php/blob/c7886ac5311b42a5ea81f9ecaeb131270e005b61/src/Renderer/HtmlRenderer.php) groups nested quote and list chains.

Rust's medium comparison input measured 7.77 ms/op at pin and 7.92 ms/op at main in CPU time. Large measured 87.26 and 87.18 ms/op. The AST-variant medium input measured 10.98 and 12.13 ms/op, but that row had a much wider sample spread than the comparison input. The comparison input's wall ratios were 1.11 at medium and 1.08 at large size; those differences did not recur in the paired CPU run. At quote depths 64, 128, and 192, render allocation counts were 12, 13, and 14 at both revisions. Depth-192 quote rendering requested 300,639 bytes for 78,158 output bytes at both revisions. List render allocation counts were 15, 16, and 16; depth-192 requested bytes were 601,703 for 297,607 output bytes at both revisions. Parse allocation counts matched. Depth-192 parse requests rose by 2.0% for quotes and 0.9% for lists. The [quote renderer](https://github.com/markup-carve/carve-rs/blob/7d2fd546e2d9cb484fda3d365348317c0f3d293b/src/render.rs) writes into the caller's `String`.

The completed scaling suites passed on the tested mains: [JavaScript](data/engine-checkup-2026-10-15/js-perf-tests.log) 108 selected performance tests, [PHP](data/engine-checkup-2026-10-15/php-scaling-tests.log) 219 tests with 48,066 assertions, and [Rust](data/engine-checkup-2026-10-15/rust-perf-tests.log) 105 isolated guards. The paired runs support a JavaScript CPU increase on the medium comparison input; the larger and variant rows are less conclusive. They do not establish a Rust CPU or render-allocation regression. PHP's parser peaks remain recorded costs at the measured main commit.
